Deploy your first application with full version control and audit trails. Each deployment records a snapshot of your configuration, with a message and author. You can restore a previous snapshot as a draft and deploy it again.

## Create Your Account

Head to [dashboard.suga.app/signup](https://dashboard.suga.app/signup) and complete the signup process. You'll create an organization and pick the region it runs in. Every environment in the organization runs in that region, so choose the one closest to your users.

## Create a Project

Click **New project** in the dashboard, then **Create empty project**. Your project is created and the canvas opens automatically.

This guide starts from an empty canvas so you can add a function by hand. You can also [import a GitHub repository](/concepts/projects#import-from-a-github-repository) or start from a template.

## Add a Function

Click **Add** on the canvas (or right-click empty space) to open the Add palette, then select **Function**. A new Deno function appears on the canvas with a default Hello World handler.

## Configure Public Access

<Steps>
  <Step title="Select the function">
    Click on the function you just added to open the properties panel.
  </Step>

  <Step title="Add a public URL">
    Open **Settings → Networking**. Under **Addresses**, click **Add public URL** and choose port `8080`, then confirm with **Add public URL**.

    Functions default to port `8080`. Check it appears under **Service ports**. Public HTTPS traffic on port 443 is forwarded to that port.

    Suga provisions a TLS certificate, configures DNS, and routes public HTTPS traffic to your function. You get a URL like `https://k3f9x2mq7p1a-production-a1b2c3d4.us-central1.suga.run`.
  </Step>
</Steps>

## Deploy

Click **Deploy** in the environment's changes banner. Review the changes, enter a **Message** (for example, "Initial deployment of Hello World function"), then confirm with **Deploy**. You can also click **Generate** to create a message from the changes.

Deploy applies the saved draft for the whole environment. If the dialog lists a blocker, fix it before continuing.

## Test Your Function

Once deployed, open the HTTPS URL under **Settings → Networking → Addresses**. You should see a JSON response: `{ "message": "Hello from Deno function!" }`.

<Check>
  Your first function is live on the internet with HTTPS!
</Check>

## What We Just Did

In addition to deploying a function, you've created a versioned, auditable infrastructure deployment:

1. **Deployment History** - Your deployment is recorded with a commit message, timestamp, and author. Open **History** in the canvas to view it.
2. **Restore Configuration** - Open a past deployment in History, choose **View on canvas**, then **Restore as draft**. Review and deploy the restored configuration. This does not restore volume data.
3. **Environment Cloning** - You can create a new environment that clones this one, giving you an isolated copy for testing changes.
4. **Complete Audit Trail** - Every future change will be tracked with who, when, and why.

Suga automatically handled:
- TLS certificate provisioning via Cloudflare
- DNS configuration and Cloudflare CDN setup
- WAF and DDoS protection
- Load balancing
- Zero-downtime deployment orchestration

All infrastructure changes are now version controlled, just like code. No configuration files, no multi-minute deployments, no lost history.
